Adding a new species

Every sheet in this project is generated from one source SVG per species, processed through a deterministic four-step pipeline. Adding a new species means staging the SVG, registering the metadata, and asking for a rebuild. This page documents everything needed to do that cleanly.

4 deterministic transforms 1 metadata row per species 5 derivative files per species 6 downstream sheets · auto-pick up

01Three-step procedure

The full add-a-species procedure. Steps 1 and 2 are yours; step 3 is mine.

STEP 1

Drop the SVG in uploads/

02What the pipeline does

Five derivative files per species. The simplified → unified → squeezed chain is the main line; unified-original branches off the source to keep the rich seam strokes.

03Source SVG conventions

The pipeline trusts a few structural assumptions about the source SVG. New icons should match — if they don't, flag it and we'll widen the rules.

filename
Lowercase, space-separated genus species.svg. No diacritics in the filename even if the latin name has them. Example: tylopilus felleus.svg.
viewBox
Any aspect — portrait, landscape and square are all handled. The unify step computes the actual content bounding box from path geometry, not the declared viewBox, so an off-centre or oversized viewBox is fine.
seam-stroke layer
A top-level <g stroke-width="2.00" fill="none" stroke-linecap="butt"> containing stroke-only paths that trace the boundaries between filled regions. Removed in simplify, preserved in unified-from-original.
filled paths
A sequence of <path fill="#xxxxxx" d="…"></path> entries for each coloured region. Paths must use absolute commands (uppercase M, L, C, Q, …) — relative is supported but the source tracer always emits absolute.
background
The first filled path is typically fill="#ffffff" covering the canvas with mushroom-shaped holes. Always stripped.
internal white fills
Additional fill="#ffffff" paths may exist for white space between adjacent mushrooms in clustered species. Stripped by default. If white is a real diagnostic colour for your species, flag it in step 3 and I'll preserve those paths.
precision
Source coordinates use 2 decimals over a ~1000–1500-unit canvas. The simplifier rounds to 1 dp (sub-pixel at hero size), the squeezer to integers in the 0–1000 unified canvas.
arcs
Arc commands (A) are supported. Bbox is computed with a conservative endpoint+radius expansion — if a new icon uses unusually large arcs, the unify step will slightly over-pad it.

04Metadata schema

icons/species-data.js is a single JS file with two exports. SPECIES drives the order and labels; SIZES drives the filesize readouts. I update SIZES automatically on rebuild. 

// One row per species. Order = display order across every sheet.
window.SPECIES = [
  …existing 19 entries…,
  {
    id:    "tylopilus-felleus",        // unique kebab-case
    file:  "tylopilus felleus.svg",    // matches uploads/ filename
    latin: "Tylopilus felleus",
    de:    "Gallenröhrling",           // German common (diacritics OK here)
    en:    "Bitter bolete"             // English common
  },
];

// Filesize report, keyed by filename. Maintained by the rebuild step.
window.SIZES = {
  "tylopilus felleus.svg": { orig: 88704, simp: 36201, sq: 24853 },
  …
};

05The four transforms · detail

Every transform is deterministic — same input always produces the same output. If the pipeline logic changes, all species can be re-derived with "rebuild all".

01Simplify

uploads/ → icons/simplified/
  • Strip the XML prolog and comment blocks.
  • Drop the entire seam-stroke <g stroke-width="…" fill="none" stroke-linecap="butt">.
  • Drop every <path fill="#ffffff" …></path>.
  • Replace encoded newlines (&#xA;) inside d= with spaces.
  • Remove vector-effect="non-scaling-stroke" attributes.
  • Round each numeric token in d= to 1 decimal, trim trailing zeros after the decimal point.
  • Collapse multi-space runs; drop space between command letters and following digits.

02Unify

icons/simplified/ → icons/unified/
  • Parse the SVG with DOMParser.
  • For every <path>, <ellipse>, <circle> compute the geometric bbox. Path bbox tokenises d= and tracks pen position through M/L/H/V/C/S/Q/T/A/Z and their relative variants. Cubic and quadratic control points are included for a conservative outer bound; arcs are bounded by ±radius around the chord midpoint.
  • Union all bboxes → content bbox (x, y, w, h).
  • Compute scale = 900 / max(w, h) (so content occupies 90 % of the canvas).
  • Compute tx = 500 − (x + w/2) × scale, ty = 500 − (y + h/2) × scale.
  • Emit <svg viewBox="0 0 1000 1000"><g transform="translate(tx ty) scale(s)">…</g></svg>.

03Squeeze

icons/unified/ → icons/squeezed/
  • Read the wrapper transform; strip the <g>.
  • For each path d=, parse commands + parameters; for each numeric parameter: absolute coord → v × scale + translate; relative coord → v × scale; arc radius → v × scale; rotation and flags → unchanged.
  • Round every value to integer.
  • Apply the same baking to <ellipse> / <circle> attributes.
  • Merge consecutive same-letter command runs (L 5 6 L 7 8 → L5 6 7 8), including implicit-L after M.
  • Drop space between letter and digit; let negative signs absorb their leading space.

04Unify-from-original

uploads/ → icons/unified-original/
  • Same as transform 02, but applied to the original SVG.
  • Only fill="#ffffff" paths are stripped — the seam-stroke layer is preserved.
  • Result: a 1000 × 1000 icon with the rich source detail.

06Anomalies the rebuild reports

Heuristics that flag a new species for human review. None are blocking — they print a note you can choose to act on.

Flag What it means · what to do
extra-white-fills Source has more than one fill="#ffffff" path. The first is always the canvas background; additional ones are usually internal gaps to strip (the default) but could be a legitimate diagnostic feature. Confirm with you.
tight-bbox-margin Content bbox margin in the source is under 2 % on any side. Usually fine, but worth a glance — the unify step still re-frames to 5 % so this only matters if the original was meant to extend off-canvas.
unusual-aspect Content bbox aspect > 3:1. Very tall or very wide species will appear small inside a square — flagged so you can decide if that's a problem.
squeeze-ratio-outside-65-75% The squeezed output is unexpectedly large or small relative to the unified file. Probably benign — different command mixes compress differently — but a large deviation suggests something weird in the source.
path-bbox-failed A path contained tokens the bbox parser couldn't interpret. The unified file falls back to the next-largest bbox; the icon may be off-centre. Send me the path and I'll extend the parser.

07Manual checklist after rebuild

Open each sheet in turn and find the new species. Tick what passes; if something fails, send me the name and a short description and I'll dig in.

Sheet C · Comparison The simplified version should be visually indistinguishable from the original at hero size and at marker size. Watch for missing internal features, broken silhouettes, or transparent holes.
Sheet D · Unified The new icon should sit visually centred inside its 1000×1000 square. Tall species hit top/bottom; wide species hit left/right. Markedly off-centre = path bbox got thrown off by an outlier.
Sheet E · Squeezed @ 300 px The icon should read clearly on all four backgrounds (sand / cream / white / charcoal). The centre crosshair should bisect the visual mass of the silhouette.
Sheet F · Unified (from original) Same centring check as D, plus: no white halos on cap edges, no white squares between clustered mushrooms. If either appears, additional internal white-fill paths need stripping — flag it.
Sheet B · Simplified The new species appears in the filesize table. The simplified ratio is 30 – 45 % of original. Outside that range = inspect.
All sheets · pin row Inside a 56 px teardrop marker, the icon should still read at a glance (silhouette recognisable). If not, the species may need a more aggressive shape simplification before being added.
